## Fixtures and auth

On initial volume creation, the load-only PostgreSQL bootstrap hook writes a catalog marker binding the run ID, hash, issuer and application database name. After app bootstrap, use the guarded Compose wrapper to run `run --rm --no-deps load-init init` once. `infra.compose.loadseed base --seed 10` creates approximately 2,000 browsable cases per accessible workspace and a separate foreign canary. It uses the shipped fictional customer, seeded message counts of 1–20, and runtime repositories. Each accessible workspace has up to 100 browse proposals and waiting-input runs. Closed historical cases provide selectivity for the status filter. The three fixture users share the same roles across the two accessible workspaces and have no foreign membership. Retain the emitted manifest with actual case, message, run, proposal and event counts.

Before each write stage, use `infra.compose.loadseed wave` with the same seed, a stage-specific name, the scheduled workflow count including warm-up, and `--warm-slots`. It creates independent simulator state and a fresh 15-minute proposal per relevant case, with known refusal controls. An advisory lock serializes wave admission under the 900-binding cap. The expiry control has a persisted presentation and an elapsed proposal timestamp. Its worker expiry job is deferred past the control window. Use a fresh volume for each repeat, with the same logical wave name and seed. Keep the raw stage-start expiry observations. Treat a partial seed as a failed setup and use a fresh disposable volume for a rerun.

Pass the private denied IP and hostname lists on every invocation. For a non-loopback target, DNS must return exactly the privately recorded `--expect-ip` IPv4 address. The driver rejects any IPv6 answer and dials the checked numeric address with the original Host and TLS server name. It requires the overlay-only 32-byte hex token and verifies the limiter setting. The public profile has no token mount and answers 404 at the marker path. The generator makes no proxy or cross-origin redirect requests.

Setup uses the deploy verifier's real Dex form flow, paced at roughly one login per second. Each session has an in-memory cookie jar and selects a workspace through the API. It verifies `/me`, observes Origin and CSRF requirements, and sends expected context headers. The setup reports login latency separately and discloses three unique principals. ## Workloads and pass rules

| Workload | Offered work | Stage rule |
|---|---|---|
| W1 browse | 1, 2, 4, 8, 16 and 32 rps. Absolute caps of 50 rps and 64 in flight. Twenty-slot shuffled blocks contain five case lists, three case details, three message pages, two case-proposal pages, five exact-version proposal details and two run snapshots. Each block adds one Bob inbox read within the overall offered rate. | p95 ≤500 ms, at least 99% of offered slots succeed within 2 s and achieved completion rate ≥95% of offered. |
| W2 SSE hold | 10, 25, 50 and 100 distinct nonterminal streams with 2 rps W1. Record time to headers, first event, heartbeat gaps, connection errors, reconnects and continuity. Reconnect requests resume with the last event ID. | W1 probe meets its rule. Each stream is reconciled with its database sequence and canonical payload digest. |
| W3 writes | 0.1, 0.2, 0.5 and 1 workflow/s with 2 rps W1. Analyst consent uses `If-Match` and a stable idempotency key. Bob reads the bound proposal and records a decision. Completion is observed via the terminal SSE event and receipt. Run separate batches of 1, 5 and 20 distinct cases, all released together after warm-up. | W1 probe meets its rule. All decision HTTP p95 ≤1 s and approval acknowledgement to terminal p95 ≤10 s. Allow at most ⌊1% × offered measured workflow slots⌋ dispatch drops. Require zero started workflow failures. |

The W3 dispatch accounting rule was adopted before any SUT measurement data was collected. Slots dropped as `missed_slot` or `overflow` stay in the offered denominator. The checker lists them under `not_dispatched` with their slot index and reason and verifies zero effects, including consent, decision or approval, execution, jobs and simulator version changes. Any effect is a correctness violation. Reports show measured dispatch misses and their allowance, warm-up drops, and started workflow failures across the stage. The send-lag p99 limit remains 5 ms. The workstation pilot requires zero W3 misses across all 26 offers, including two warm-up offers. At 0.5 workflows/s over a 180 s measurement window, 90 measured offers also give an allowance of zero. The allowance first reaches one at 100 measured offers.

All stages require zero correctness violations and no growing due-job backlog. Setup checks foreign REST and SSE canaries with all fixture sessions. Each limiter-off stage repeats one REST and one SSE canary during measurement and records them as instrumentation outside the workload mix. The checker verifies tenant isolation, race and replay outcomes, stale 409s, response-to-row accounting, exact database event sequences, terminal projections, local and simulator receipt hashes, and a simulator version increment of one per approved case. Before and after inventories cover decisions and approvals, executions, jobs in every state, and messages across both accessible workspaces and the foreign canary. The checker independently counts dead jobs, overdue queued jobs and expired leases in all three workspaces. A prior wave's expiry job may finish when the same run and proposal version have a matching persisted decision. Refusals require zero execution and no simulator version increment. The race cohort is 10% and replay cohort 5%, rounded with a minimum of one. The same reviewer identity uses two concurrent sessions and conflicting request reasons so the losing request encounters a genuine 409. The consent replay repeats the same key and body. Decision replay repeats the same bound request under the same reviewer identity. The expected byte-identical bodies and one audit row are checked for each logical write.

The versioned profiles are in `infra/load/`. Timed trial defaults are 60 s warm-up, 180 s measurement and 90 s drain. The short pilot uses workstation-only durations. Stop an exploratory workload at its first failing stage. Repeat the highest passing and first failing stages three times each. Report every planned attempt, including missing evidence and retries. For a capacity aggregate, use `--attempts` with a chronological JSON array of objects carrying `run`, `stage`, and `rate` (W1 rps). A correctness failure disqualifies the rate and stops subsequent trials. If the coordinator authorizes a replacement after investigating the cause, append the retry using the same environment, full stage configuration, profile, target and seed, plus `replaces` (the original run label) and a `reason` recording the authorization. Retain both artifacts. Only a replacement with verified evidence clears the earlier failure. Replacement of invalid generator evidence uses the same record. Abort on a correctness failure, SUT OOM or restart, two consecutive readiness losses, measured send-lag p99 above 5 ms or generator CPU above 50%. The rate-limiter run expects public-rule 429s and is excluded from capacity.

Each offered slot has a precomputed monotonic intended time. At the first send, drop any arrival more than the smaller of 5 ms and a quarter of its period late. Late drops and in-flight overflow stay unsent. Their dispatch lateness contributes to the generator validity gate. Reports regenerate the schedule and require exactly one record for every warm-up and measured slot. Generator CPU evidence must cover the measured window at 1 s cadence, with a maximum 1.5 s gap and at least two distinct samples. The dispatcher does not queue load for a later burst. Latency for W1 is intended arrival through completion. W3 reports decision HTTP latency across all attempts, including expected 409s and errors, with a breakdown by status or no response. A missing or mismatched attempt latency row invalidates the stage before decision p95 is computed. Time from approval acknowledgement to terminal receipt is a separate metric. JSONL stores timing, status and bounded error codes. Unknown rule IDs are recorded as `unrecognized`. REST and SSE error responses must match the closed error envelope, including foreign-canary 404s. SSE evidence contains sequence, identifiers and a canonical payload digest. Extra fields in the closed event schema are a correctness violation. Every repeat is shown with median and range. Three repeats give no confidence interval.

```bash

"$RUN/gen-venv/bin/python" -m pip install --require-hashes --only-binary=:all: -r infra/load/requirements.txt
export PYTHONPATH="$PWD/packages/policyops_contracts/src"
"$RUN/gen-venv/bin/python" -B -m scripts.loadgen \

```

The report compares median due count and age in the first and last 30 measured seconds and checks the end-of-drain count. For certification, host and database observations must cover measured start through drain end at 1 s cadence with a maximum 1.5 s gap. Container observations must span the same interval at 5 s cadence with a maximum 6.5 s gap. Each series must bracket the window with the required measurement fields present. Counter deltas use complete snapshots bracketing measurement. A coverage gap leaves the stage unverified. Use an isolated diagnostic run for `pg_stat_statements`. Take `EXPLAIN (ANALYZE, BUFFERS)` outside timed runs after at least one real login. The checker captures the repositories' bound SELECTs for the case pages, messages, event poll, session lookup, roles, inbox and bindings. It runs the app SELECTs under runtime workspace scope and the identity SELECTs through the auth role.
